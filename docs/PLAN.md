# План ядра boardtest для Karabas Go / Mini / Mini G

Начат 2026-11-22. Цель: одно ядро проверки платы вместо `karabas-go-core-test` (тест ZXDOS) и
`karabas-go-core-sdram-test` (MemTest MiSTer). Из старых ядер берём только идеи (перечень проверок,
перебор частоты SDRAM с авторежимом), код пишется заново. Основа — SoC ядра `karabas-go-core-menu`
(VexRiscv, RPC, градиент и палитра `menu_compose`, шрифты Noto 4 бит, звуки, мышь, AT к ESP) и его
стиль экранов.

## Решения (пользователь 2026-11-22)

1. **Вариант A: интерфейс целиком в BRAM**, SRAM и SDRAM полностью свободны и проверяются
   разрушающими тестами. Тестер работает и показывает диагноз на плате с мёртвой памятью (у menu код
   и кадр в SRAM: с оборванной линией SRAM он не запустится).
2. **Тот же стиль, что у меню**, точная копия не нужна: градиент, палитра, сглаженный шрифт, кнопки
   / панели, курсор мыши — но экран из знакомест, а не кадровый буфер с блиттером.
3. **Новый репозиторий `karabas-go-core-boardtest`**. Старые test / sdram-test — в архив после
   релиза (спросить).
4. **Имя в списке ядер: «Karabas Board Test»** (`name` в `core.json`): ядро видно в меню.
5. **Id `boardtest`**, файл `boardtest.kg` (новое ядро, `cores/test.kg` старого не заменяется на месте).
6. **Выхода из теста в интерфейсе нет**: пользователь сам нажимает Ctrl+Alt+Backspace (Global Reset
   прошивки, пункт OSD с этой клавишей в `core.json`).
7. **Репо публичное сразу** (`andykarpov/karabas-go-core-boardtest`); PR на каждую фазу в master.

## Архитектура

```
 VexRiscv rv32im (75 МГц) ── код + данные в BRAM (LOAD из ROM-секции .kg, CPU в сбросе до LOAD END)
        │ MMIO
        ├── видео: menu_compose (градиент + палитра ARGB) + слой знакомест (BRAM) + курсор → VGA / HDMI
        ├── mbist_sram  ─┐ аппаратные тесты памяти, CPU только задаёт режим и читает итог:
        ├── mbist_sdram ─┘ линии, march C-, случайные, байты, удержание, запас скорости / частоты
        ├── kg_mcu2 + kg_l2_rpc (SYS: плата, версия fw, RTC; HID; CORES для выхода)
        ├── периферия: SD2 SPI, CF/IDE PIO, FT812 SPI, UART ESP, FDD (Go), ESP32 (Mini G)
        └── звук: генератор тонов L / R, ADC PCM1808, лента, BEEPER, MIDI_TX, пики в MCU
```

### Видео: слой знакомест (вид согласован 2026-11-22: `docs/img/f0_mock_main.png`, `f0_mock_sram.png`)

- Кадр 800 × 600 @ 60 (как у menu, clk_sys 40,91 МГц), градиент фона — аппаратный `menu_compose`,
  его цвета — из `[ft812]` `karabas.ini` по RPC CFG, как у меню (пользователь).
- Знакоместо 10 × 20 (80 × 30). Клетка: тайл + цвет fg 4 бит + фон bg 4 бит (палитра 16 × {альфа 4,
  RGB 24}; bg 0 = прозрачно, виден градиент). Пиксель = bg + (fg − bg) · a / 15, альфа тоже.
- **Шрифт — 8 × 8 OSD прошивки (CP866), строки удвоены (8 × 16)**, по центру клетки, ASCII 32..126,
  1 бит (пользователь: «выглядит отлично», лучше Noto Mono; UTF-8 не нужен). Крупные цифры часов и
  даты — тот же шрифт × 2 (16 × 32, 2 × 2 клетки), только `0-9 : /`.
- **Логотип** — монохромный логотип Mini (firmware `ui2.c` `logo_full`, m и n исправлены как у
  цветного — firmware PR #165), × 4 пропорционально = 224 × 64, тайлами; чёрточки белые.
- Фигуры со сглаживанием (16 уровней): концы кнопок, углы и края рамок, подчёркивание, полосы
  индикатора (дорожка того же цвета с прозрачностью 1/3), точки состояния.
- Кнопки в один ряд клеток; **точка состояния — на самой кнопке** в отдельной клетке слева (как
  маркер разделов Setup меню).
- Генератор атласа `src/sw/tools/atlas.py`, макет кадра `src/sw/tools/mockup.py` (модель пикселей
  железа), исходные данные в `src/sw/assets` (шрифт и логотип — копии из прошивки).
- Курсор мыши — аппаратный спрайт. После проверки SRAM — полноэкранные тестовые картинки из SRAM:
  бэклог.

### Бюджет BRAM (52 RAMB16 = 104 КБ), проверяется в Ф0

Атлас макета: 202 тайла. Шрифт, цифры и логотип — 1 бит, только фигуры (~30 тайлов) — 4 бит:
два атласа (1 бит: ~170 × 200 бит ≈ 3 RAMB16; 4 бит: 32 × 200 полубайт ≈ 2 RAMB16) вместо одного
4-битного (~10 RAMB16).

| Что | RAMB16 |
|---|---|
| код + данные CPU (32–48 КБ) | 16–24 |
| кэши VexRiscv (I$ / D$ 4K, сгенерированное ядро как есть) | 6 |
| карта клеток 80 × 30 × 18 бит | 3 |
| атласы (1 бит + 4 бит) | 5 |
| палитра, курсор, kg_mcu2 / OSD overlay, FIFO тестов | ≈ 6 |
| **итого** | **36–44** |

## Проверки

|---|---|---|
| FPGA / MCU | DNA; частота CLK_50 относительно MCU; плата, ревизия, версия fw по RPC SYS | все |

| SPI flash | **всегда N/A**: микросхему никто не запаивает, её выводы в части ядер — ЦАП старых Mini (пользователь 2026-11-22); пункт в списке остаётся | — |
| SD2 | детектор, CMD0 / 8 / ACMD41, CSD (объём), чтение сектора 0, скорость | все |
| SD1 | наличие, объём через RPC | все |

| FT812 | REG_ID по SPI, на Mini / Mini G картинка через FT_DE / FT_CLK | Go, Mini, Mini G |
| ESP8266 | AT, AT+GMR, скан Wi-Fi, CTS | все |
| ESP32 | по SPI: модуль отвечает и сообщает версию — этого достаточно (пользователь 2026-11-22) | Mini G |
| Звук | тон отдельно L и R, развёртка; DAC (PCM5102 / сигма-дельта Mini), BEEPER (Go) | все |
| Вход | ADC PCM1808 — индикатор уровня; TAPE_IN — уровень и фронты | Mini, Mini G / все |
| Петли кабелем | DAC → ADC (автоизмерение уровня / частоты), TAPE_OUT → TAPE_IN | по наличию |
| MIDI | гамма на синтезаторе (MIDI_TX, MIDI_CLK / MIDI_RESET_N на Go и Mini) | все |

| Ввод | USB клавиатура (схема нажатых клавиш + сканкоды), мышь с колесом, джойстики / геймпады, кнопки платы | все |
| FDD | выбор привода, мотор, шаг, дорожка 0, оборотов в минуту по INDEX, защита записи, поток чтения | Go |

Итоговый экран ГОДЕН / БРАК по группам; режим прогона по кругу (на ночь); итог в машиночитаемом
виде через USB CDC (AT+KARABAS / RPC), чтобы стенд и проверка плат шли без экрана.

## Фазы

Одна ветка на фазу, один PR в master в конце фазы.

### Ф0. Проверка вписываемости на Mini G (`-t 2`)
- Перенос SoC из menu: VexRiscv без кэшей, код в BRAM, загрузка `LOAD` из `.kg`; `menu_compose`;
  новый `bt_tiles` (слой знакомест) + атласы из Noto; курсор.
- C: экран «привет» в стиле меню (заголовок, панель, кнопки), часы кадров, клавиатура по RPC.
- Отдельный бинарь для хоста (как `src/sw/host` menu) — кадры без платы.
- Итог: LUT, RAMB16, тайминг (75 / 40,91 МГц), кадр на плате (тестовое ядро на карте под своим
  именем).

**Итог Ф0 (2026-11-22, сборка 26112201, ветка `phase/f0`):** `bt_soc` (VexRiscv как есть, I$ / D$ 4K, программа
в BRAM 32 КБ, загрузчик пишет RAM и атласы), `bt_tiles` (80 × 30 клеток, атлас 1 бит 173 тайла 4,3 КБ + 4 бит
29 тайлов 2,9 КБ, палитра 16, курсор), верх Mini G (SRAM / SDRAM в покое, RPC SYS + CFG + CORES). Программа
5,8 КБ (без libc): главный экран макета, цвета `[ft812]`, плата и версия прошивки (SYS INFO), часы (TIME_GET),
клавиши, мышь. Симуляция `src/sim/soc/run_sim.sh` (~1 мин): два кадра совпадают пиксель в пиксель с побитовой
моделью `src/sw/tools/frame_model.py`. Mini G `-t 2`: 5601 LUT (37 %), 2198 слайсов (58 %), 31 RAMB16 + 9 RAMB8,
все ограничения выполнены, `minig-coremode` тоже. На плате (пользователь: «все отлично!», 26112201): экран как в
симуляции. Правки по итогам (26112202, тот же битстрим, новые ROM): часы и дата шрифтом 16 × 24 по высоте
логотипа (y 8..72, вариант B), 17 групп в две колонки по 9 (RTC / EEPROM, Buttons / LEDs, LED matrix); на плате
проверено по захвату (стрелки, мышь, часы).

### Ф1. Базовый набор платы, ввод, видео, звук
- Верх Mini G со всеми выводами; **базовый набор** (правило): пики звука в MCU (`audio_peaks`),
  TAPE_IN / TAPE_OUT + `kg_tape_monitor`, MIDI_TX, ADC PCM1808, FT_CLK_OUT 8 МГц.
- Проверки: FPGA / MCU, ввод, видео, звук, лента, MIDI, ADC.
- **RTC / EEPROM, Buttons / LEDs, LED matrix** (пользователь 2026-11-22): кнопки передней панели — действие `core`
  у `buttons` в `core.json` (`BTNS[1:0]` kg_mcu2; BOOTSEL / MSC с кнопок в этом ядре нет), кнопки матрицы —
  `BTNS[5:2]`; матрица — картинки из ядра через AUX (`ENABLE_AUX`, `MATRIX_CMD`), проверка глазами (Y / N);
  RTC — `SYS TIME_GET` (отвечает, секунды идут, дата правдоподобна). Светодиоды и EEPROM есть только у MCU:
  **PR в прошивку #166** (worktree), RPC SYS `3 I2C_SCAN` (какие адреса I2C отвечают: EEPROM 24C08 0x50, RTC DS3231
  0x68, HT16K33 0x70 / 0x71, PCA9536 Go 0x41) и `4 LED` (на время теста LED1 / LED2 вкл / выкл, потом снова прошивке), описание в
  `docs/link_v2.md`; слияние = релиз прошивки, только по слову пользователя. Со старой прошивкой — «N/A (firmware)».
- Экраны: главный (список групп с состоянием), страница группы, итог. **Согласование вида**
  пользователем (кадры).

**Итог Ф1 (2026-11-22, сборка 26112205, ветка `phase/f1`):** `bt_io` (DNA, кнопки, кадры матрицы + `audio_peaks`,
MIDI, ленточный вход, пики и переходы через ноль ADC) и `bt_audio` (два тон-генератора, синус / меандр, микшер,
TAPE_OUT, монитор ленты) в том же битстриме; проверки FPGA / MCU, RTC / EEPROM, Buttons / LEDs, LED matrix, Audio,
Tape, MIDI, Video, Input. Программа 19,6 КБ из 32 КБ. Mini G `-t 2`: 45 % LUT, 67 % слайсов, BRAM как в Ф0,
тайминг и `minig-coremode` выполнены. Тесты: `src/sim/io/run_io_sim.sh` (iverilog, 7 с), `src/sim/soc/run_sim.sh`
(кадры = модель), хост `src/sw/host/run.sh` (все страницы, кадры в `docs/img/f1_*.png`; вид одобрен). Прошивка #166
слита (релиз). На плате: FPGA / MCU, RTC / EEPROM (I2C 50–53, 58–5B, 68, 70, 71 — `docs/img/f1_board_rtc.png`), MIDI
(авто PASS), звук HDMI L / R, видео — по захвату; кнопки, светодиоды, матрица, Audio (DAC → line in), Input
(удержание Esc) — пользователь. Не проверены на плате: Tape (петля кабелем), джойстик.

### Ф2. Тесты памяти
- `mbist_sram`, `mbist_sdram` (RTL, свои контроллеры; SDRAM на DCM_CLKGEN как в sdram-test):
  режимы, первый сбойный адрес, маска бит, счётчики, диагноз линий.
- Симуляции против моделей с внесёнными дефектами (замкнутые / оборванные линии, залипшие биты) —
  тест должен назвать дефект (секунды).
- Экран памяти: карта линий, перебор частоты, авторежим.

### Ф3. Накопители и периферия
- SD2, CF / IDE (только чтение), FT812, ESP8266, ESP32 (Mini G),
  SD1 по RPC.

### Ф4. Автоматика

- FDD Go (может уйти в Ф5, если без платы с дисководом).

### Ф5. Go, Mini и релиз

## Риски

| Риск | Что делаем |
|---|---|
| BRAM не хватит | Ф0 измеряет; код 32 КБ, меньше крупный шрифт |
| SDRAM 166 МГц и тайминг | как в sdram-test: CLKFX_MD_MAX, TIG между доменами |
| Mini G2: CS SDRAM на T3 (FLASH_CS_N) | на T3 всегда CS SDRAM: на G он ни к чему не подключён (флеши нет) |
| Записи на чужие носители | CF / SD / flash — только чтение |
